# Product

## Register

product

## Users

Plex power users — people with large, self-hosted media libraries who want automated structure without constant manual effort. They're technically comfortable (running a home Plex server), operating on a Mac desktop, and frustrated by how chaotic large libraries become without curation. They open the app occasionally (not daily) to rebuild or update playlists in bulk.

## Product Purpose

Structly is a desktop automation tool that builds and manages Plex playlists from library metadata — grouping by studio, genre, director, resolution, and more. It eliminates hours of manual playlist curation. Success looks like: user opens app, picks a library and mode, hits Build, and gets a fully organized Plex library in minutes.

## Brand Personality

Structured. Precise. Efficient.

Voice is confident and minimal — no hand-holding, no explanations of the obvious. The tool respects the user's technical competence. Tone is dry, not playful; capable, not flashy.

## Anti-references

- **Plex's own UI** — busy, media-heavy, poster-grid aesthetic. Avoid dark layouts cluttered with thumbnails and gradients.
- **Generic SaaS dashboards** — the navy/teal/purple enterprise tool look (Notion clones, Linear clones, watered-down Tailwind admin panels). No hero metrics, no identical card grids.
- **Media center apps (Kodi, Jellyfin, Emby)** — dark, cluttered, grid-heavy interfaces designed for 10-foot TV viewing. Structly is a precision desktop tool, not a remote.

## Design Principles

1. **The tool disappears** — UI should feel lightweight and fast; the user's attention belongs on Plex, not Structly. No decorative chrome.
2. **Respect the expert** — Don't explain what a prefix is. Don't confirm every action with reassuring copy. The user knows what they're doing.
3. **Structured confidence** — Orange-on-black with grid-based layout. Editorial, not entertainment. Structly brings order to chaos; the UI should embody that order.
4. **Density without clutter** — A powerful tool that fits in one window. Pack information tightly but leave enough whitespace for the grid to breathe.
5. **Status is everything** — Progress, connection state, and log output are the feedback loop. They must always be visible and readable.

## Accessibility & Inclusion

No formal WCAG compliance target. Priority: readable contrast at all text sizes, logical keyboard tab order, and clearly visible focus indicators. No motion-sensitivity accommodations required by spec, but avoid gratuitous animation.
